# Integrated 2026.09 RC4 validation

Date: 2026-09-15. Status: **candidate, not promoted to production**. Supersedes RC3 and the RC3 ARM64 candidate (`releases/2026.09-rc.3-arm64-validation.md`). RC4 restructures the Headscale and Headplane downstream patch series (same features, same behaviour) to make future upstream rebases cheaper, and carries the ARM64 candidate's fixes: Casdoor `9d982e2d` enforces application WebAuthn policy before creating sessions (independently re-run here: `go vet` and the WebAuthn tests in `controllers` and `object` pass), the Casdoor hardener follows the real application wire schema with regression tests, the runtime renderer reads product image names from the source lock, and Headplane's build stage lets Corepack use the configured proxy. The integration worker is unchanged from RC3. The remaining production gates are unchanged (tenant scopes, public DNS/TLS and OIDC, two-device pilot with a live node expiry, Docker-host restore rehearsal).

## Why

A maintainability review of the forks found that the RC3 series mixed upstream backports with our own fixes, changed upstream helper signatures and page structure for localization, and spread branding markup through Headplane's header. Replaying the RC3 series onto the upstream `main` branches of 2026-09-15 produced 35 conflict hunks in 9 Headscale files and 5 hunks in 4 Headplane files.

## Integration

`versions.lock.yaml` pins Headscale `905ad57f`, Headplane `d5f4be6` and Casdoor `9d982e2d`; images are built as `2026.09-rc.4` for `linux/amd64` on the development host. The deployment host is ARM64: build the same commits natively there (or export a `linux/arm64` bundle) as the ARM64 candidate did; the lock is platform-neutral and `image-inputs.json` selects the platform. `docs/build-versioning.md` documents the patch-series layout and replay procedure. Integration suite: 188 tests pass.

## Sandbox and bundle

The local sandbox runs all three rc.4 product images (Casdoor `sha256:8c9c75739cf3`, Headscale `sha256:3742645045f0`, Headplane `sha256:a5b4521aa9ec`) with the retained data volumes and the rc.4 worker container in staged mode. Smoke checks after the swap: Headscale healthy with the downstream version string, the OIDC error page renders bilingual spans with the shared language control, the Apple page carries the hidden inert control, Headplane healthy behind its OIDC-only login, the ordinary-user authorization probe passes 8/8 on the new Casdoor, and the hardener reports no pending change. The amd64 bundle `fysics-bundle-2026.09-rc.4-01` is exported from the release commit that carries this file and validated with `validate_bundle` at that checkout; its checksum and the worker image ID are in the private inventory. `releases/manifest-2026.09-rc.4.yaml` is the candidate manifest; the promotion checker refuses it until the gates below are met. The deployment host is ARM64: a `release/integrated-2026.09-rc.4-arm64` branch selects `linux/arm64` and architecture-specific tags for a native server build, as the RC3 ARM64 candidate did.
